# M2 · Ground truth

**Scale:** atmosphere — §2.8's lifted-print regime, and the vacuum it fades out of.
**Modules:** `terrain.js`, `surface.js`, new `material.js`, new `paint.js`, new `print.js`
**Flag:** `?m2=1`, default-off (§7.4). Flipping the default is a separate commit.

§M2 asks for ground you can name from a still: four-layer triplanar materials,
a depth-graded ocean, far ridges as pure silhouette, and — first, because they
change every subsequent frame — §9.2's light model and §9.3's aerial
perspective.

This plan puts one thing ahead of both of those, and §0 argues for it.

---

## 0 · Sequencing, and a deviation from §6's own ordering

§M2 says *"Port §9.2 (`paint()`) and §9.3 (aerial perspective) first; they change
every subsequent frame."* This plan ports **§9.4, the print**, ahead of them.

The argument is not that the print matters more. It is that the print is the
transform every later judgement is made through:

1. **§9.2's defining feature is a hue ramp with visibly banded edges.** §9.2
   says so, and §11 lists deleting them as the archetypal PBR reflex. ACES is a
   filmic curve whose entire purpose is to compress and desaturate exactly that
   structure. Porting the light model and then scoring it through ACES measures
   the tonemap, not the light model — and §8 demands one sentence naming the
   pixel region that lost the point, which is not answerable when the curve is
   the thing eating it.
2. **Everything downstream gets tuned against the viewing transform.** Land the
   print last and §9.2 and §9.3 are tuned twice, the second time against a
   frame that no longer looks like the one they were tuned for.
3. **The print is the one act that could be built without a GPU**, which is what
   this session had. It is fragment maths with an exact CPU reference (§7.3),
   and its correctness is decidable offline.

The cost, named so it cannot be quietly dropped: §9.4 steps 5 (watercolour
softening at `0.42 × fog`) and its chroma bleed both read the fog fraction from
the alpha channel, which is §9.3's aerial perspective and does not exist yet.
They are deferred to act 2 and land with the thing that writes a distance.

## 3 · Two rulings, one uniform

§3 makes two separate rulings, and it is easy to implement one and believe you
have implemented both.

| Row | Ruling | Rides |
|---|---|---|
| 1 | OLED true-black vs. the reference's lift → **split by medium**; vacuum true `#000`, atmosphere lifted; cross-fade on entry | `uPaint` |
| 3 | AEON's `1 − exp(−1.32·c)` vs. the reference's rational curve → **the reference curve wins at surface scale; AEON's survives in vacuum**; cross-fade on entry | `uPaint` |

Row 1 is about the grade. Row 3 is about the **tonemap** — a different stage,
before the grade, and the first draft of this act got it wrong: it scaled every
graded step by `uPaint` and ran the reference's rational curve at all scales.

That is not a subtle difference. The two curves diverge hardest exactly where
the cosmic web lives:

| linear in | `1 − exp(−1.32·c)` | rational print | ratio |
|---|---|---|---|
| 0.02 | 0.0261 | 0.0693 | 2.66× |
| 0.20 | 0.232 | 0.385 | 1.66× — widest absolute gap, 0.153 |
| 1.00 | 0.733 | 0.703 | 0.96× |

Measured on the frame rather than the curve: the cosmic web's mean luminance
went 0.204 through ACES → **0.381** through the rational curve. Nearly the whole
gain was the toe. With row 3 implemented, vacuum reads 0.124.

So `tonemap()` takes `uPaint` as well:

```glsl
vec3 tonemap(vec3 x, float paint) {
  x = max(x, vec3(0.0));
  return mix(tonemapVacuum(x), tonemapPrint(x), paint);
}
```

Both curves are monotone and both send 0 to 0, so the blend is monotone at every
`uPaint` and true black survives the whole descent rather than only its
endpoints. Both properties are asserted in `tools/verify.js`, not assumed.

### Where `uPaint` comes from

`paintForScale()` in `print.js`, called once per frame from `main.js` before
`post.render()`:

| scale | `uPaint` |
|---|---|
| cosmic, galaxy, system, blackhole | 0 |
| surface, clouds | 1 |
| planet | `clamp(1 − (alt − 0.0003)/0.35, 0, 1)` — full print by ~2 km, none above ~1 planet radius |

The planet scale is the interesting one because it spans both media: it begins
in orbit, which is vacuum, and ends on the ground, which is not. The same
descent that drives the hyperzoom drives the grade, which is what §3 asks for.

## 5 · Four deliberate deviations from the reference

Each one is forced by an invariant the reference does not have to satisfy,
because the reference is one valley in one atmosphere and AEON is six scales.

1. **The tonemap cross-fades.** The reference has one medium and one curve.
   §3 row 3. See §3 above.
2. **Paper tooth and vignette are scaled by `uPaint`.** The reference applies
   both unconditionally. A warm-dark vignette multiplies the frame toward
   `(0.62, 0.60, 0.66)`, which in vacuum is a tint over a field that should be
   black, and paper tooth on a true-black field is a lift with extra steps.
   §2.8.
3. **The dither is gated on luma.** §9.4 step 8 is a flat ±0.5/255; applied at
   zero it rounds half the vacuum to 1/255. The gate is
   `smoothstep(0, 1.5/255, luma)`, so true black stays exactly black and the
   first visible step — which is where banding actually lives — is dithered at
   full strength. §2.8 against §9.4, and both survive. (This was already M1's
   resolution for the same collision; act 1 carries it into the print.)
4. **The grade pass gives up its vignette and its grain.** `post.js` has had a
   per-world grade since before either milestone: lift, gain, saturation,
   vignette, grain. Under M2 the last two belong to §9.4, which owns them and
   scales them by medium. Two vignettes and two grains in series is the
   double-grade §9.4's step order exists to prevent — and in vacuum the grade's
   grain was worse than redundant. See §6.

The resonance keeps lift, gain and saturation. Those are a world's colour
intent, not the print.

## 6 · One defect the new curve exposed

The grade pass adds `g · uGrain · min(3l + 0.08, 1)` in linear light, ungated by
medium, with a neutral default of `uGrain = 0.02`. The vacuum scales never set
`gradeSettings` — only `planetscale.js` and `surface.js` do — so the cosmic web
had been getting film grain and a 0.12 vignette all along, at a scale where
§2.8 says the background is true `#000`.

ACES concealed it. Its toe near zero is flat enough that a ±0.0008 floor rounds
back to 0 at 8 bits. AEON's own curve has roughly **12× the slope at the
origin** and prints the same floor as 1/255.

*The grain was always wrong. Only the tonemap that hid it has changed.* That
sentence is the reason this act was worth doing before the ones §M2 lists first:
the print is not just a look, it is the instrument that makes the other errors
measurable.

## 7 · The bloom pedestal, and why act 2 has to composite it

Removing the grade's grain did not restore black. Bisecting the chain at runtime
found the real source, and it is structural.

| configuration | frame at true `#000` |
|---|---|
| as shipped | 0.0% |
| bloom pass disabled entirely | **76.2%** |
| bloom strength 0 | 75.8% |
| grade pass disabled | 0.0% |

`UnrealBloomPass` composites five mip levels, the coarsest at 1/32 resolution
with a separable kernel that spans the frame. Every bright pixel therefore
contributes to *every* pixel. In an atmosphere that is veiling glare and it is
welcome; in vacuum it is a pedestal under a field that must reach zero.

No setting removes it. The full sweep, at the cosmic scale, seed 20250601,
a = 0.55, 640 × 400, `m1=1&slab=1&comp=1&q=desktop&m2=1`:

| knob | `#000` | lit | mean | peak |
|---|---|---|---|---|
| shipped — radius 0.75, threshold 0, strength 0.85 | 0.0% | 99.0% | 0.123 | 0.885 |
| radius 0.25 | 0.0% | 87.6% | 0.114 | 0.911 |
| radius 0 | 0.0% | 78.9% | 0.110 | 0.922 |
| threshold 0.15 | 30.4% | 22.3% | 0.023 | 0.765 |
| threshold 0.4 | 40.7% | 19.5% | 0.020 | 0.770 |
| strength 0.15 | 22.0% | 19.8% | 0.020 | 0.762 |
| bloom floor 0.0012 | 0.0% | 75.8% | 0.098 | 0.801 |
| bloom floor 0.005 | 28.9% | 42.8% | 0.053 | 0.778 |
| radius 0 + floor 0.003 | 36.4% | 43.6% | 0.068 | 0.843 |

Every row that recovers black deletes the web to do it. Nothing reaches the
76% that turning the pass off reaches. Zeroing `bloomFactors` for the coarse
mips does not help either, and is worth knowing why: `lerpBloomFactor` mixes
each factor toward `1.2 − factor`, so at radius 0.75 setting a factor to 0
*raises* that mip's weight to 0.9.

**The conclusion is that this pass cannot satisfy §2.8, at any setting.** The
fix is the reference's structure — a bright pass, a bounded blur chain, and the
composite performed *inside* the print (`c += bl · uBloomAmt`, reference
4421–4422) where it can be firewalled and where §9.4's step order puts it
anyway. That is act 2, and this measurement is the reason act 2 does it.

What act 1 ships instead is the mechanism, not the fix: `firewallBloom()`
patches the composite material — at runtime, so `/vendor` stays byte-verifiable
per §10 — to add §11's **first** NaN firewall, which was missing, and a
`uBloomFloor` knob driven by `?bfloor=`. The floor defaults to **0**, so act 1
does not touch the halo. Every replacement the patch makes is checked, and a
miss throws: a patch that silently fails to apply is precisely the defect
§M0's shader gate exists to catch.

## 10 · Two gaps in the instrument, closed

Neither is M2 work. Both were found by M2 work failing in ways the instrument
should have caught first.

**`tools/parse.js` — the parse gate.** A backtick inside a GLSL template
literal, in a *comment*, terminates the template and turns the rest of the
shader into JavaScript. This has now cost two runs. Every downstream tool
reports the same useless symptom — the page did not boot — because the module
never parsed. `node --check` is not the guard it looks like: given a file
containing an `import`, it detects ESM, declines to parse, and exits 0. Copying
to `.mjs` makes it check for real. It runs first in `tools/check.js`, ahead of
everything that launches a browser to discover the same thing more slowly.

**`tools/shadercheck.js --flags`.** The compile gate flew the bench route once,
unflagged. §7.4 says milestone work is built behind a default-off flag — so the
gate was compiling the build nobody is iterating on and reporting green while
every new shader in the repo went unchecked. It now flies the route once per
flag combination, defaulting to the shipped build plus `m1=1&m2=1&slab=1`.

## 13 · Budgets at risk (§5)

The print replaces `OutputPass`, so the pass count is unchanged: one full-screen
fragment pass either way. What it adds per pixel is three `pn2` evaluations
(each four `hash12` calls, one `sin`/`cos` pair, and a quintic fade), two
`smoothstep`s, a `pow` in the sRGB encode that `OutputPass` was doing anyway,
and the vignette's `pow`. The bloom patch adds one `max` and one `equal` to a
pass that already runs.

Estimated well inside the ≤12 ms CPU / fragment headroom, but **estimated is not
measured** — §5 is a correctness property and this needs `?bench=1` on real
silicon. It has not had it. That is the single number act 1 cannot supply from
here.
